# 需要使用牌事件 & 预使用牌事件

> 领域权威定义。来源：用户口述（2026-07-18）。参考旧项目 `needUseCard` / `preUseCard` 实现。
> ⚠️ **用户指示**：整个使用的架构需要重新设计，本篇为规则定义 + 重新设计分析。

---

## 一、触发关系

"需要使用此牌"（NeedUseCard）→ 确定使用方式 → "预使用牌"（PreUseCard）→ "使用牌事件"（UseCardEvent）：

- **需要使用牌** = 角色尚未确定怎样使用牌时触发 → 走完 need 流程若开始使用 → 自动进入预使用
- **预使用牌** = 角色已确定怎样使用牌（牌名/对应实体牌/目标均已敲定）→ 完成后触发使用事件

**实现中两者均不作为独立的事件**，而是客户端交互 + 卡牌选择流程。

## 二、需要使用牌事件（NeedUseCard）

### 触发条件

一名能使用某牌的角色：
- 在此牌的**默认使用时机**要使用此牌，或
- 不在此牌的默认使用时机**需使用**、且未对此牌对应的实体牌的选择标准有说明

→ 触发"需要使用此牌"事件。

### 三时机（规则）× 两时机（实现简化）

| 时机 | 规则内容 | 实现 |
|---|---|---|
| **需要使用此牌时❶** (need1) | 〖护驾〗〖激将〗〖酒诗①〗〖勤王〗〖八卦阵〗〖刺槐〗延时；◆ 发动时**同时声明牌名+提前选择目标**（视为无色无花无点数但有对应实体牌），后续目标选择**跳过合法性检测** | **询问式发动**——服务端询问"是否发动XX？" |
| **需要使用此牌时❷** (need2) | 〖傲才〗〖活墨〗〖饰非〗〖卫境〗〖陷嗣②〗〖振赡〗〖讨袭〗延时；珠联璧合→无实体桃；◆ 同上——声明牌名+提前选目标 | **按钮式发动**——客户端技能按钮（如武圣/丈八同时亮起），玩家直接点→技能自动设置选牌标准和目标 |
| **需要使用此牌时❸** (need3) | 修改选择此牌对应实体牌的标准（武圣/龙胆/急救/奇策/丈八蛇矛/烂银甲等数十个技能） | 与❷合并——点击技能按钮已暗含"不发动❶的技能+选此技能+定选牌标准" |

> 用户注（实现简化理由）：为减少询问量，武圣和丈八按钮同时亮起，玩家点击按钮直接按技能要求选牌使用。把点击按钮当作"不发动武圣+发动丈八"的合二为一操作。

**非技能路径**：以"不为上述任意一个操作的方式"使用 = 客户端不选技能时，默认方式——需要用什么就选手牌里同名牌（`need2` 的兜底）。

◆ 出牌阶段空闲时间点通过任意操作使用的杀**计入阶段使用次数**。

**◆ 未开始使用 = need 结算结束（不进入预使用）；开始了使用 = need 结束 → 预使用事件触发**。

## 三、使用合法性规则

### 一张牌能被使用的条件（三关）

1. 不能受技能效果影响禁止使用（`Prohibit_UseCard` StateEffect）
2. 使用过同名牌的次数未达上限（**杀的特殊规则**见下）
3. 合法目标数 ≥ 额定目标数下限 且 ≠ 0

### 杀的使用次数规则

- 只有在**出牌阶段空闲时间点使用**的杀才计入次数 + 受次数限制
- "无次数的限制"：可突破上限使用，但**会计入次数**（例：高顺〖陷阵〗后对大乔杀不限次、计入次数→不能再对第三者杀）
- "不计入限制的次数"：不使计数增加（例：〖龙吟〗令此杀不计入）
- ◆ 一回合内使用杀次数上限 +/-X = 此回合**每一个出牌阶段**上限均 +/-X

### 合法性规则的来源

| 来源 | 内容 |
|---|---|
| 牌面"使用目标"产生 | 距离关系限制 + 目标数量（额定上下限） |
| 技能产生 | 目标限制规则（如空城、帷幕、同疾） |
| 游戏系统规则（仅两条） | ①判定区有延时锦囊实体牌者**不是同名延时锦囊**的合法目标；②**判定区封印**者不是延时锦囊的合法目标 |

### 额定目标数量的计算

- "所有……"：下限=合法目标数、上限=所有
- "X 名/张"：上下限均 = X
- "至少 X"：下限=X、上限=合法目标数
- "至多 X"：下限=1、上限=X
- "<A>和<B>"：下限=A下限+B下限、上限=A上限+B上限（**两种目标各至少一个**）

### 关键词

- "A对B使用牌" = 除 B 外其他角色在预使用中不是此牌合法目标
- "角色也成为牌的目标" = 所有角色使用此牌时这些角色都成为目标（同义扩展）
- 距离关系限制规则由牌面"使用目标"产生，目标限制规则可由技能/系统产生

## 四、预使用牌事件（PreUseCard）

旧项目实现为向客户端发起使用牌的询问。

### 流程

1. **声明牌名**（用牌名/【杀】种类/【无懈】种类/【酒】【桃】使用方法）。**在此牌的预使用流程中若需使用流程已声明过则不再声明**
2. **确定选择对应实体牌的标准**：无对应实体牌→略；特定实体牌→直接赋（如慷忾直言傲才）；默认→手牌区一张同名牌名（「鏖战」状态修正桃→替换对应牌）
3. **确定选择范围** = 标准 ± 扩缩技能（木牛流马②扩；奋钺鸡肋讥谀潜袭司敌黠慧义绝限）
4. **选择对应实体牌**，根据牌的数量定虚拟牌：
   - 1 张→实体牌↔虚拟牌唯一对应 + 花色/点数=实体牌的（例：帷幕下黑色田→杀色同，不合法）
   - >1 张→唯一对应 + 颜色/花色/点数按规则（都同色→有色无花；不同色→无色无花无点数）
   - 无对应实体牌→无色无花无点数（不能判断与另一张牌的颜色/花色/点数相同）
5. **选择 n 个合法目标**，建立目标列表，**逆时针编号** [T1…Tn]，从小到大排序

◆ 若因执行技能效果的"对目标使用无实体牌"而使用，且发动技能时已过合法性检测 → 选此目标**跳过合法性检测**（"需对…"不受此豁免）。

◆ 目标已在需要时提前选择过 → 以提前选择的为准。

### ◆ 步骤未履行 = 终止预使用、不触发使用事件

若因 **need1/need2 技能**触发的预使用中任意步骤未履行 → 终止、视为**未发动过此技能**；因**need1/need2 技能的延时类效果**触发的 → 视为**未执行过此效果**。

## 五、架构重设计分析（用户指示）

### 当前问题（用户自述）

1. 整个需要对牌的事件架构有问题——实现没作为事件但规则定义为事件
2. need1/need2/need3 三层在实现中被压成两时机 + 按钮式技能绕过了逐问
3. 按钮同亮的"合二为一"操作（点武圣=不选丈八+选武圣）是交互优化但绕过了规则上的顺序
4. 预使用是整个选择流程的容器——但选牌、选目标在客户端一次完成，未走服务端拆分步骤

### 关键约束

- need1 类技能（询问式）= 服务端可主动弹询问（护驾激将八卦阵）
- need2/3 类技能（按钮式）= 客户端按钮亮起、玩家点按钮 = 同时完成"不选need1" + "选此技能" + "定选牌标准" + "执行选牌选目标"
- 非技能路径 = 客户端默认选牌（手牌同名牌）—need 不介入
- "需要使用牌时❸"在旧项目注册为 `usecard_need3` 但无用（已合并到 need2）
- need1/need2 技能发动后若预使用步骤失败 → **视为未发动过**（无消耗、无副作用）

### 接收的设计要求

1. 以 [old/resgsv1] needUseCard + preUseCard 为参考
2. 结合技能系统重新设计 need1/need2 的触发链路
3. need2 按钮式技能 = 等效"不发动need1" + "选此技能" + "一步完成选牌选目标"
4. 预使用 = 声明牌名+选实体牌+选目标的一次性客户端询问（多步选择器）
5. "未见实体牌=标准"选择范围/扩缩容由 cardSelector 统一实现
6. 虚拟牌的对应关系与信息继承
7. 合法性三来源 + 杀次数（空闲时间点/无限制/不计入三语义）+ 额定目标数枚举
8. 目标提前选择且提前选过的豁免合法性检测

**重新设计方案**：2026-07-19 用户拷问确认全部 26 条决策。以下为最终架构设计。

---

### 5.1 三层边界

| 层 | 职责 | 实现 |
|---|---|---|
| **need1** | 询问式技能（护驾/激将） | 标准 trigger 流程，EventManager.trigger 扫描触发技 |
| **need2** | 按钮式技能（武圣/丈八） | 并入使用牌询问——ChooseManager 单 session 携带可用 need2 技能列表，客户端按钮自行决定 |
| **need3** | 修改选牌标准 | 废除（旧项目武圣挂 usecard_need3，新设计并入 need2） |
| **pre 层** | 选牌→选目标的一次性客户端多步选择 | ChooseManager 单 SelectSession：选牌 step(card) → [声明牌名 step，仅 1 对多转化] → 选目标 step(player) |
| **use 层** | 触发 UseCardEvent 进入使用流程 | `room.useCard()` 双签名：签名 1 直接触发事件 / 签名 2 发起使用牌询问，询问返回自动调签名 1 |
| **打出** | 使用 - target step | 可选"需要打出的牌名"→可发技能；无名→只限范围禁技能；无合法性检测（仅查禁止打出） |

### 5.2 合法性检测

- **乐观 Pre-check**：`room.canUseCard()`，传入牌名或虚拟牌对象。属性盲、布尔返回。三关：Prohibit → 次数（history 查询当前 PhaseEvent.phaseId 之后空闲时间点计数）→ 目标数 > 0
- **Post-check**：传入确定虚拟牌对象→结果可判定状态效果解除的限制（如"红色杀无距离限制"）。客户端用于渲染可选目标和阻断确定按钮
- 牌名版本用于默认时机检测（只关心"杀能不能用"）；确定虚拟牌版本用于复杂技能条件预判
- 传入 useModifiers > 状态 modifiers（临时优先）

### 5.3 选择器与 UseModifiers

- **选牌方法** = `SelectConfig(type='card')`：默认=手牌同名牌，need2 技能覆盖（武圣=红色牌，丈八=任意两张，奇策=全部手牌）
- **目标限制** = `SelectConfig(type='player')`：默认=牌定义 targetSelector，need2/need 时注入可动态覆盖
- **UseModifiers**：独立于 SelectConfig 的对象——无次数限制 / 无距离限制 / 不计入次数 / 是否可用技能 / 借刀子目标等，不污染选牌对象
- **声明牌名 step** = 客户端自动推断：转化 1 对 1（龙胆/武圣）直接确定无需 step；转化 1 对多（奇策/张让）插入声明 step
- **借刀子目标** = targetSelector 附加可选"子目标"字段，不进目标列表/不触发 assign/become 时机

### 5.4 CardUse 定义与次数管理

- **CardUse** = sgs 全局注册 + 房间首张牌创建时 deepCopy 注册到房间（允许运行时某张牌的属性被临时修改）
- CardUse 属性：默认使用时机 + 目标限制 + 效果。**无 method 字段**——桃/酒的不同用法由调用端上下文决定（出牌阶段空闲点 vs 濒死事件）
- CardUse 按默认使用时机**预索引**，Pre-check 不遍历全卡牌定义
- **杀次数** = 零记录字段，纯 history 查询（当前 PhaseEvent.phaseId + 空闲时间点过滤 + UseModifiers 扣减不计入次数部分）。每出牌阶段独立计数
- 合法性检测 → `Room.canUseCard()` 方法

### 5.5 UseCardEvent 统一类

- 一个 UseCardEvent 类替代旧三子类，`buildTriggers()` 按 card.type + 卡牌使用技能信息动态生成时机序列：
  - **card.type=装备/延时锦囊** → 预结算收尾直接结束（装备入装备区虚拟牌消失、延时锦囊入判定区留虚拟牌）
  - **卡牌使用技能提供"目标是牌"信号** → 闪/无懈/金蝉剔除声明使用牌后~成为目标后段
  - **判定阶段延时锦囊系统触发（无使用者）** → 规则技能内部调 room.useCard 签名 1，仅循环 A-B 内容，单目标一次
  - **其余（基本牌/普通锦囊，目标角色）** → 全套 15 时机 + 循环 A-B
- 统一入口：`room.useCard()` 双签名（签名 1 直接触发事件 / 签名 2 发起使用牌询问）
