# 体力事件族（LoseHp / ReduceHp / RecoverHp / ChangeMaxHp）

> 领域权威定义。来源：用户口述（2026-07-18）。实现参照新项目 `DamageEvent.ts`（LoseHp/ReduceHp）与 `HpEvent.ts`（RecoverHp/ChangeMaxHp），旧项目 `event/types/event.hp.ts`。
> 注：加/减体力上限在实现中**合并为体力上限改变事件**（ChangeMaxHpEvent，用户注）。

---

## 失去体力事件（LoseHpEvent）

### 失去体力结算开始前

能发动：〖黄巾天兵符②〗。

### 失去体力结算中

**首先进行扣减体力结算**（嵌套 ReduceHpEvent）。

#### （1）失去体力后（losehp_after）

能发动：〖诈降〗。

### 失去体力结算结束后

暂时没有作用。至此失去体力流程结束。

---

## 扣减体力事件（ReduceHpEvent）

扣减体力结算中：**扣减体力前 → 扣减体力时 → 扣减体力后** 三个时机。

分两种触发来源：

### 1. 在伤害事件中产生的扣减体力事件

首先：
- 若将扣减体力的角色受到的是**属性伤害**且处于**连环状态** → 其**重置**
- 若将扣减体力的角色受到的是**不为连环伤害的属性伤害**且有其他处于连环状态的角色 → 于此伤害结算结束后会**触发连环**
- 确定**最终的伤害值**

（1）**扣减体力前**（reducehp）——检测〖狂骨〗的发动条件是否满足。

（2）**扣减体力时**（reducehp）——能发动：〖不屈（1v1）①〗。

然后受到伤害的角色一次性扣减 X 点体力：将其武将牌以右移的方式减少 **min{其体力牌上露出的勾玉数, X}** 个其体力牌上露出的勾玉数（X = 确定的最终的伤害值）。

> 注："扣减体力的时候最多遮住现在露出的所有勾玉"——即 hp 按数量减少、inthp 受 [0,] 钳制；最终伤害值可大于当前体力值（hp 可变负）。

（3）**扣减体力后**（reducehp_after）——能发动：〖连计〗的延时类效果、〖乱战①〗、〖伤逝〗。

然后若其**体力值为 0**，进行**濒死流程**（嵌套 DyingEvent）。

### 2. 在失去体力事件中产生的扣减体力事件

流程与"在伤害事件中产生"的区别：

- **不触发**"属性伤害 + 连环状态 → 重置 + 触发连环"（不是伤害，无属性、无连锁）
- "确定最终的伤害值"改为"确定**最终失去的体力点数**"
- 扣减体力时技能列表相同（〖不屈（1v1）①〗）
- 扣减体力后技能列表仅〖伤逝〗（无〖连计〗〖乱战①〗——这两者来自伤害的额外上下文）

### 扣减体力结算结束后

暂时没有作用。至此扣减体力流程结束。

---

## 回复体力事件（RecoverHpEvent）

首先确定回复的体力点数（同**回复值基数**，见 [values.md](../terms/values.md)）。

### （1）回复体力前

暂时没有作用。

然后其**一次性回复 X 点体力**：将其武将牌以左移的方式增加 **min{其体力牌上未露出的勾玉数, X}** 个露出的勾玉数（X = 确定的回复的体力点数）。

### （2）回复体力后（recoverhp_after）

能发动：〖不屈（1v1）②〗、〖良助〗、〖伤逝〗、〖淑慎〗、〖先辅〗的延时类效果。

### 回复体力结算结束后（recoverhp_end）

暂时没有作用。至此回复体力流程结束。

---

## 减体力上限流程（ChangeMaxHpEvent 负向）

首先确定减的体力上限点数 X。

### （1）减体力上限前

暂时没有作用。

**执行**（Y = 减前体力牌所有勾玉数 - X；Z = 减前露出的勾玉数）：

- **X < 体力上限**：更换一张勾玉数为 Y 的体力牌。若减前**未露出的勾玉数 ≤ X** → 露出所有勾玉并将**体力改为 Y**（体力压到新上限）；**> X** → 露出 Z 个勾玉（体力值不变）
- **X ≥ 体力上限**：其**死亡**

然后若其体力上限**为 0**：**终止**减体力上限流程（后续时机不生成），其**死亡**。

> 关键裁定：体力上限归零的死亡**不能被挽救**（不进入濒死流程，不能发动〖涅槃〗类技能），且若因技能减上限致死，**并非**技能发动者"杀死"（无来源死亡）。例：邓艾体力上限 1 时发动〖凿险〗减 1 点上限 → 直接死亡；庞统体力上限 1 被〖潜袭〗减 1 点上限 → 直接死亡、非马岱杀死、不能发〖涅槃〗。

### （2）减体力上限后（change_maxhp_after）

能发动：〖伤逝〗、〖威重〗。

### 减体力上限结算结束后（change_maxhp_end）

暂时没有作用。

---

## 加体力上限流程（ChangeMaxHpEvent 正向）

首先确定加的体力上限点数 X。

### （1）加体力上限前

暂时没有作用。

**执行**：更换一张勾玉数为 Y 的体力牌，露出 Z 个勾玉（Y = 加前体力上限 + X；Z = 加前露出的勾玉数——**体力值不变**）。

### （2）加体力上限后（change_maxhp_after）

能发动：〖伤逝〗、〖威重〗。

### 加体力上限结算结束后（change_maxhp_end）

暂时没有作用。

## 实现映射（体力事件族汇总）

| 规则 | 新项目 | 状态 |
|---|---|---|
| 失去体力 = 嵌套 ReduceHp | `LoseHpEvent` → `ReduceHpEvent` 内联 | ✅ |
| 扣减体力 = 伤害值确定 + 体力条移动 + 濒死检测 | `ReduceHpEvent` → 修改 hp/inthp → DyingEvent | ✅ |
| 护盾吸收 | shield 优先于 hp 减少 | ✅（damage 测试覆盖） |
| 伤害值 > 当前体力不阻断 | hp 可负（shiled 吸收情况不同：shield 挡住部分伤害、hp 下为受伤） | ✅ |
| 连环重置 + 触发连环时机 | 在 ReduceHp 的"扣减前"位置（伤害事件产生的版本） | ⚠️ 现代码护盾/受伤前未执行连环重置——M4 连环对接时补 |
| 扣减体力前/时/后三时机 | `ReduceHp`（前）、`ReduceHp`（时）、`ReduceHpAfter`（后） | ✅ |
| 失去体力前/后/结束时四时机 | `LoseHpStart/LoseHp/LoseHpAfter/LoseHpEnd` | ✅ |
| 完整链 Damage→ReduceHp→Dying→Death | 已在 dying-death 测试中覆盖 | ✅ |
| 回复钳制 min{未露出勾玉数, X} | RecoverHpEvent check() 钳制回复量（不超过 losshp） | ✅ |
| 回复时机 | `RecoverHpStart/RecoverHp/RecoverHpAfter/RecoverHpEnd` | ✅ 裁定 R6：**全部保留**——`RecoverHp`（回复体力时）供规则集未收录的武将技能使用 |
| 加减上限合并 | `ChangeMaxHpEvent` 单事件（用户注一致） | ✅ |
| 上限归零 → 终止流程 + 死亡 | 上限 ≤0 触发死亡（测试覆盖） | ⚠️ "不进濒死、不能挽救、无来源死亡"细节待核对 |
| 减上限压体力（未露出数 ≤X → 体力改为 Y） | — | ⚠️ hp=min(hp, 新上限) 逻辑待核对 |
