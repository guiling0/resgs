# 领域文档（Domain Docs）

工程技能在探索代码库时，应按以下方式消费本仓库的领域文档。

## 探索之前先读

- 仓库根目录的 **`CONTEXT.md`**（领域词汇表）
- **`docs/adr/`** —— 阅读与即将工作的区域相关的 ADR

如果这些文件不存在，**静默继续**。不要指出它们缺失，也不要建议预先创建。`/domain-modeling` 技能会在术语或决策真正敲定时惰性创建它们。

## 文件结构

本仓库为单上下文（single-context）布局：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-client-pixi-vite.md
│   └── 0002-ai-utility-rules.md
├── shared/
├── server/
└── client/
```

## 使用词汇表中的词汇

输出中提到领域概念时（issue 标题、重构提案、假设、测试名），使用 `CONTEXT.md` 中定义的术语，不要漂移到词汇表明确避免的同义词。

所需概念尚未进入词汇表时，这本身是个信号——要么你在发明项目不使用的语言（请重新考虑），要么存在真实缺口（记录下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

如果你的输出与既有 ADR 相矛盾，明确指出而非静默覆盖：

> _与 ADR-0001（客户端选型）相矛盾——但值得重新讨论，因为……_
