# 扩展文档规范

`extensions/` 存放扩展内容的全量文档：每模式、卡牌、武将、扩展项目各一档，**逐实体建档**，不论文档膨胀。扩展文档是规则词条引用区②（信息文档）的聚合源。

## 目录结构

| 目录          | 内容                                  | type      | id 前缀       |
| ----------- | ----------------------------------- | --------- | ----------- |
| `modes/`    | 每模式一档（身份、国战等）                       | `mode`    | `modes/`    |
| `cards/`    | 每卡牌一档（含技能档案）                        | `card`    | `cards/`    |
| `generals/` | 每武将一档（含技能档案）                        | `general` | `generals/` |
| `projects/` | 每扩展项目一档（扩展说明，对应 `extension/` 下每个项目） | `project` | `projects/` |

## frontmatter 约定

```yaml
---
title: <中文标题>
type: card | general | mode | project
id: <前缀>/<注册标识>    # 稳定 ID，全局唯一，链接锚点
rules:                  # 依赖的规则词条/事件时机 ID（穷举聚合依据）
  - events/use-card
  - events/pindian
tags: [<分类标签>]
---
```

- `id`：与扩展注册标识一致（牌名/武将真名/模式名/项目标识），不随标题变化
- `rules:`：声明本档逻辑所依据的规则词条/事件时机 id。kb:check 校验引用存在；kb:refs 反向聚合到规则词条引用区②

## 各类文档内容

### cards/（type: card）

- 牌名、类别/副类别（基本/锦囊/装备等）
- 标注描述：人类自然语言，面向玩家
- 详细描述：按规则词条拆解逻辑，面向 AI
- 使用/打出定义要点、涉及时机

### generals/（type: general）

- 基础信息：体力、势力、性别
- 技能档案（每技能）：
  - 标注描述：面向玩家
  - 详细描述：面向 AI，按规则词条拆解
  - 涉及时机
- 资源信息（插画/语音，命名与路径遵循 AGENTS.md 资源约定）

### modes/（type: mode）

- 模式说明、玩家配置
- 与基础规则的差异（身份/势力/胜利条件等）
- 涉及的特殊规则词条

### projects/（type: project，扩展说明）

对应 `extension/` 下每个扩展项目一档：

- 项目标识、包名、用途
- 内容清单：含有的模式/牌/武将（链接到各自档）
- 依赖声明：`rules:`
- 构建/测试/发布信息（可选）

## 建档与聚合

新增扩展实体（模式/牌/武将/项目）时：

1. 在对应目录写档（标注 + 详细描述）
2. frontmatter 声明 `rules:`（依据的规则词条/时机）

> 索引重建、一致性校验与引用区聚合在 git 提交时自动完成（post-commit hook）。

## 扩展完成后归档流程

每完成一个扩展（由用户告知后）执行一次归档，步骤：

1. **建扩展说明文档**：`projects/<项目标识>.md`（type: project），类似 API 文档结构，说明该扩展内实现了什么（含有的模式/牌/武将清单并链接到各自档）
2. **武将/卡牌归档**：`generals/`、`cards/` 逐实体建档
3. **以代码 `GeneralData` 属性为准**：武将/卡牌的基础信息与描述以代码提供为准，不另行杜撰
4. **学习（不重复学习）**：
   - 通过提供的标注描述与详细描述学习（已归档过的描述不重复学习）
   - 总结代码结构进行 guide 学习并归档（已归档过的代码结构不重复学习）
5. **技能归档**：针对每一个技能，放入规则文档的时机穷举或词条穷举中

> 落档的具体格式待首个真实扩展完成后完善，届时同步更新本规范。
