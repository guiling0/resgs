### aigc_res 资源替换规则

当用 `aigc_res/` 目录下的资源替换场景/预制体中已有资源时，必须按以下流程执行。

> `aigc_res/` 仅作为 AIGC 生成资源的临时存放区，正式资源必须在 `resources/` 目录下管理，不要直接引用 `aigc_res/` 下的资源。

#### 2D 资源替换（图片、纹理等）

1. **复制资源到 resources**：将 `aigc_res/` 下的文件复制到 `resources/` 下与被替换资源相同的子目录（如被替换资源在 `resources/ui/icons/`，则复制到该目录）
2. **更新场景/预制体引用**：用新资源路径替换场景或预制体文件中对应的 `skin`/材质等引用（`_$uuid` 字段直接填资源路径，引擎自动解析）
3. **更新 resource_list.json**：将对应条目的 `path` 更新为新资源路径，`status` 保持 `"matched"`

#### 3D 物体替换（模型等）

1. **复制模型到 models 目录**：将 `aigc_res/` 下的模型文件复制到 `resources/models/` 对应子目录
2. **判断是否需要解包**：
   - 被替换节点引用的是 `.lh` 预制体，而新资源是 `.fbx`/`.glb` 等美术源文件 → 需要先解包
   - 被替换节点引用的是 `.fbx`/`.glb` 等美术源文件，新资源也是 `.fbx`/`.glb` → 直接替换，无需解包
   - 新资源本身就是 `.lh` 文件 → 直接替换，无需解包
3. **解包流程（如需要）**：调用 `unpackModel`（支持传入路径，自动转换）将 `.fbx`/`.glb` 解开生成 `.lh` 文件，然后将生成的 `.lh` 文件复制到 `resources/` 对应目录
4. **更新场景/预制体引用**：用新资源路径替换 `_$prefab` 字段（直接填路径如 `resources/prefabs/3d/hero.lh`，引擎自动解析）
5. **更新 resource_list.json**：将对应条目的 `path` 更新，`status` 保持 `"matched"`

## 迭代开发模式

当用户在已构建完成的项目上提出功能变更时，主 Agent 应自动进入迭代开发模式，而非重跑 `/build` 全量流水线。用户也可通过 `/iterate` 命令显式触发。

### 项目状态判断

通过以下条件判断项目是否已构建过：
- 需求文档存在且不为空
- 源码目录下存在 `.ts` 代码文件

两个条件全部满足 → 项目已构建，优先走增量迭代路径。

### 意图分级

根据用户请求的变更范围，分为四个级别：

| 级别 | 判断条件 | 示例 |
|------|---------|------|
| **Level 1: 直接改代码** | 变更局限于单个已有脚本的内部逻辑，不涉及新模块或接口变更 | "把跳跃高度从 5 改成 8"、"修复碰撞检测偏移" |
| **Level 2: 局部迭代** | 需要新增或修改 1-2 个模块，可能涉及新事件或接口 | "角色增加跳跃功能"、"添加计分UI" |
| **Level 3: 跨模块迭代** | 影响 3 个及以上模块，或涉及场景结构变更 | "增加多关卡系统"、"添加敌人AI和战斗系统" |
| **Level 4: 建议全量构建** | 变更范围接近重做，超过现有模块的 50% | "把跑酷游戏改成射击游戏" |

### 各级别处理策略

**Level 1 — 直接改代码**
1. 读取需求文档和相关代码了解上下文
2. 定位目标代码文件，直接修改代码
3. 编译验证（`AssetManagement → waitAssetBusy`）
4. 更新工作流状态迭代记录

**Level 2 — 局部迭代**（需要新增场景节点或脚本）
1. 更新需求文档（追加变更段，不重写已有内容）
2. 生成增量 game.json（只包含新增/修改的指令），运行 execute.mjs
3. 填充新脚本的业务逻辑，编译验证
4. 更新工作流状态迭代记录

**Level 3 — 跨模块迭代**
1. 更新需求文档
2. 更新 GameEvents.ts（如有新事件）
3. 生成增量 game.json（含 createNode/removeNode/setProperty + 新脚本的 waitAssetBusy + mountScript），运行 execute.mjs
4. 填充所有新脚本的业务逻辑，编译验证
5. 更新工作流状态迭代记录

**Level 4 — 建议全量构建**
- 向用户说明变更范围过大，建议使用 `/build` 重新构建
- 如用户坚持增量，按 Level 3 处理但发出风险提示

### 增量更新原则

- **需求文档**：在文末追加 `## 增量变更 vN` 章节，保留原有内容不变
- **代码文件**：只修改受影响的文件，不触碰无关模块
- **GameEvents.ts**：新增事件常量，保留已有事件不变
- **场景变更**：通过增量 game.json + execute.mjs 执行（createNode/setProperty/removeNode/mountScript），无新脚本时可省略 waitAssetBusy 和 scripts
